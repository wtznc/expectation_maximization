# Expectation-Maximization (EM) Algorithm

Implementation of the EM algorithm for Gaussian Mixture Models — with real-world examples that show *why* it matters.

## What Does This Algorithm Do? (Plain English)

Imagine you have a big bag of measurements — customer spending amounts, sensor readings, blood test results — but you don't know that the data actually comes from **several distinct groups mixed together**. You can't see the group labels. All you see is the raw numbers.

The EM algorithm looks at that mixed-up data and figures out:

1. **How many groups** are hiding in the data (you give it a guess).
2. **What each group looks like** — its average value, how spread out it is, and how common it is.
3. **Which group each data point probably belongs to.**

It does this by repeating two steps — **Expect** and **Maximize** — over and over until the answer stops changing.

## Real-World Use Cases

### 1. Customer Segmentation (Retail)

A store sees thousands of monthly spending amounts but doesn't know which customers are budget shoppers ($25 avg), regular shoppers ($120 avg), or premium shoppers ($450 avg). EM discovers these three groups automatically so the marketing team can send the right offers to the right people.

### 2. Anomaly Detection (Network Security)

A server logs response times for every request. Most traffic is normal (~45 ms), but a small fraction (~8%) of requests are suspicious and take much longer (~320 ms). EM separates normal from abnormal traffic and gives the security team a data-driven alert threshold.

### 3. Species Classification (Biology)

A botanist measures petal lengths of flowers in a meadow. Two sub-species are mixed together but look similar to the eye. EM splits the measurements into two groups (1.5 cm vs 4.8 cm average) — no labels needed.

### 4. Sensor Calibration (Manufacturing / IoT)

A factory accidentally logs temperature readings from a cool zone (22 °C) and a heated zone (85 °C) into the same data stream. EM unmixes them so engineers can monitor each zone independently.

### 5. Medical Diagnostics (Healthcare)

A hospital screens blood glucose levels. The population contains healthy individuals (~90 mg/dL) and undiagnosed pre-diabetic patients (~135 mg/dL). EM separates the groups and suggests a screening cutoff so doctors know who needs follow-up testing.

> Run `python real_world_examples.py` to see all five scenarios simulated with realistic data.

## How the Algorithm Works (The Math)

We model the data as coming from a **mixture of K Gaussian (normal) distributions**. Each data point was generated by one of the K components, but we don't know which one.

### Parameters

| Symbol | Meaning |
|--------|---------|
| K | Number of Gaussian components |
| x_i | The i-th observed data point (i = 1 … N) |
| pi_k | Mixture weight of component k (how common it is; all weights sum to 1) |
| mu_k | Mean of component k |
| sigma_k | Standard deviation of component k |

### The Probability Model

The probability of observing a data point x under the full mixture is:

```
p(x) = sum over k=1..K of [ pi_k * N(x | mu_k, sigma_k^2) ]
```

where `N(x | mu, sigma^2)` is the Gaussian probability density:

```
N(x | mu, sigma^2) = (1 / sqrt(2 * pi * sigma^2)) * exp(-(x - mu)^2 / (2 * sigma^2))
```

### Step 0: Initialisation

Pick starting values for all parameters:

```
pi_k = 1/K              (uniform weights)
mu_k = quantile_k(data) (spread across the data range)
sigma_k = std(data) / K (initial spread)
```

### Step 1: Expectation (E-step)

For each data point x_i and each component k, compute the **responsibility** — the probability that component k generated x_i:

```
r(k, i) = pi_k * N(x_i | mu_k, sigma_k^2) / sum over j=1..K of [ pi_j * N(x_i | mu_j, sigma_j^2) ]
```

This is just Bayes' theorem. The denominator normalises so that responsibilities sum to 1 across components for each data point.

### Step 2: Maximization (M-step)

Update each parameter using the responsibilities as soft assignments:

**Effective count of points in component k:**

```
N_k = sum over i=1..N of r(k, i)
```

**Updated weight:**

```
pi_k = N_k / N
```

**Updated mean:**

```
mu_k = (1 / N_k) * sum over i=1..N of [ r(k, i) * x_i ]
```

**Updated standard deviation:**

```
sigma_k = sqrt( (1 / N_k) * sum over i=1..N of [ r(k, i) * (x_i - mu_k)^2 ] )
```

### Repeat

Alternate between E-step and M-step until the **log-likelihood** stops increasing (or a maximum number of iterations is reached):

```
log L = sum over i=1..N of log( sum over k=1..K of [ pi_k * N(x_i | mu_k, sigma_k^2) ] )
```

Each iteration is guaranteed to increase (or maintain) the log-likelihood — the algorithm always converges.

### Why It Works

The EM algorithm solves a chicken-and-egg problem:

- **If we knew the group labels**, we could easily compute the best parameters for each group (just take the mean and std of each group's points).
- **If we knew the parameters**, we could easily assign labels (just pick the most likely component for each point).

We know neither, so EM alternates: the E-step pretends the current parameters are correct and assigns soft labels; the M-step pretends the soft labels are correct and updates the parameters. This back-and-forth provably increases the likelihood at every step.
